# Research: keep the hub private, and limit the damage if it is reached

The question: which guards make a Meat Mode hub reachable only from a private network (tailnet, LAN, VPN), and limit what an attacker gets if one is reached anyway. The hub can wake coding agents on the user's machines, so control of the hub is close to control of those machines. Reader notes: `boundary.md` (Q1), `peers.md` (Q2), `auth.md` (Q3, Q4); brief: `brief.md`. Grades: A controlled or large n, B one team or small n, C anecdote, V vendor guidance.

## Findings

1. **One layer fails; peers that recovered added two.** OpenHands' agent server bound 0.0.0.0 with no key until 1.37.1 (2026-08), which now binds loopback without a key and warns on a wildcard bind (V/B). OpenClaw requires a token even on loopback and rejects proxied requests unless `trustedProxies` is set (V). Exposure is fast and large: 21,639 OpenClaw gateways within a week (Censys, 2026-01), 1,862 MCP servers with all 119 sampled unauthenticated (Knostic, 2025-07), ComfyUI instances exploited for mining (Censys, 2026-04) (B). (`peers.md`)
2. **A private bind did not save OpenClaw.** CVE-2026-25253 (CVSS 8.8) leaked a token and drove the loopback gateway from the victim's own browser through missing WebSocket Origin checks; the fix added a confirmation step (A, advisory). Meat Mode already checks Host, Origin and Sec-Fetch-Site on every `/api/` call. (`peers.md` 2)
3. **Same-host proxies make internet traffic look local.** Tailscale Serve, cloudflared and Docker or rootless podman port forwarding all hand the hub a loopback or bridge address as the peer, whatever the real client (C/V). A peer-address check alone therefore cannot tell a Funnel or tunnel request from a tailnet one. (`boundary.md` 4)
4. **Tailscale marks what it forwards.** Serve strips inbound `Tailscale-User-*` and `Tailscale-Funnel-Request` headers, sets the identity headers for tailnet users, and Funnel traffic carries `Tailscale-Funnel-Request: ?1` and no identity (V, plus source read). The headers are trustworthy only when the hub listens on loopback behind Serve; tagged nodes get none (V). (`boundary.md` 1)
5. **Forwarding headers are attacker input unless a known proxy wrote them.** Jellyfin treated WAN logins as LAN behind a misconfigured proxy and misread an IPv4-mapped address in `X-Forwarded-For` (B, issues #13966, #13054). Cloudflare appends to a client-sent `X-Forwarded-For`, so its leftmost entry is forged at will (V). **Inference:** using those headers only to refuse (any public address anywhere in the chain) needs no trust in them, because a forger can only make a request look more public. (`boundary.md` 4, `peers.md` 4)
6. **Go's `IsPrivate` is not an access check.** It excludes the shared range Tailscale uses, and its maintainers say not to use it for trust decisions (C). Build the allowlist from named prefixes after `Unmap()`. (`boundary.md` 3)
7. **A DNS check catches Funnel and public domains, as an alarm.** Funnel publishes public records for the `ts.net` name, but MagicDNS answers locally, so the check must ask a public resolver; stale Funnel records lingered about 4 hours in one report (C). (`boundary.md` 5)
8. **Login on a private network is still the norm, and the 90-day session is long.** ASVS 5.0 7.3.1 and 7.3.2 require an idle timeout and an absolute lifetime (V). Home Assistant's `trusted_networks` skips the password and MFA, the posture Meat Mode's "no password, Tailscale only" matches (V). (`auth.md` 4, `peers.md` 4)
9. **Passkeys conflict with a private hub in the Android app.** Android needs Digital Asset Links fetched by Google's servers, so `assetlinks.json` must be public (V, plus one C report); `go-webauthn` is still v0 with breaking changes in 0.18.0 (V). Browser passkeys are unaffected. (`auth.md` 1, 2)
10. **Agent limits must hold where the agent runs.** OWASP LLM01: no fool-proof prevention of prompt injection; least privilege and human approval of high-risk actions (V). Claude Code permission rules and its OS sandbox are enforced by the harness, not the model; `auto` mode's guard is a classifier reading the same text (V). (`auth.md` 5)

## Trials run

- **Rootless podman port publishing hides the client** (B, measured on the dev box, netavark): a container published with `-p` saw every request as coming from the podman bridge gateway, whether the client used loopback, the LAN address or the tailnet address. A peer check inside a container sees nothing useful.
- **Tailscale Serve strips forged headers** (B, measured): a request carrying forged `Tailscale-User-Login` and `Tailscale-Funnel-Request` reached the backend with neither, from `127.0.0.1`. A request from the serving node to itself got no identity header either, so whether another device's request carries one through a Tailscale Service is still open.

## Guard set (Inference), ranked

Do, in this order:

1. **Header guard on every request** (pages, `/api/`, `/bridge/`, `/healthz`): refuse with `403` when `Tailscale-Funnel-Request` is present, or when any address in `X-Forwarded-For`, `Forwarded`, `X-Real-IP`, `CF-Connecting-IP` or `True-Client-IP` is outside the private set (loopback, RFC 1918, the shared range, ULA, link-local, after `Unmap()`), or when the direct peer is outside it. Deny-only, so forged headers can only make a request look more public. No setting turns it off. `MEAT_MODE_TRUSTED_NETWORKS` adds a LAN's own prefixes (such as its global IPv6 prefix), capped at /16 for IPv4 and /48 for IPv6. The peer part is blind inside a container (trial above); it still guards a hub run as a plain binary or with host networking.
2. **Public DNS check of `MEAT_MODE_PUBLIC_URL`** through a public resolver: a global address stops the hub at start with a plain message. Hourly afterwards a global address is logged and shown as a warning in Settings; it does not stop the hub, because a stale record or a home domain pointing at a router that forwards nothing is common (finding 7). When no public resolver answers, the hub logs that it could not check.
3. **Agents are switched on at the agent machine only.** The app can turn a repo's Agents off but not on; turning on takes `meat-mode bridge agents on <repo>` on the bridge machine. A taken-over hub then cannot widen what agents may touch (findings 2, 10).
4. **Mandatory login.** Remove the no-password mode: a hub with no password serves only the setup claim. Sessions get an idle timeout (14 days, renewed also by the device-token calls of devices the session registered, so a phone that lives on notification buttons keeps push) and keep the 90-day absolute lifetime. The hub asks for the password again, within the last 10 minutes, before creating a bridge token or changing the password (finding 8).
5. **The bridge refuses a public hub.** `meat-mode bridge pair` and every dial refuse a hub whose address resolves outside the private set or `MEAT_MODE_TRUSTED_NETWORKS`.
6. **Browser hardening, the parts missing:** the hub already sends a CSP with `frame-ancestors 'none'`, `Referrer-Policy: no-referrer` and `X-Frame-Options: DENY`. Add `Cross-Origin-Opener-Policy: same-origin` and the `__Host-` cookie prefix on https; the rename logs every device out once.
7. **Docs and defaults:** Tailscale (Serve or a Tailscale Service on loopback) or a LAN reverse proxy only; publish the container port on `127.0.0.1` or the tailnet address, never `0.0.0.0`; warn against Funnel, Cloudflare Tunnel and router port forwards; calendar feeds work only for calendar apps on the user's own devices.

Maybe, after a trial from a second device: require a non-empty `Tailscale-User-Login` when the operator declares the hub sits behind Serve (`MEAT_MODE_BEHIND_TAILSCALE=1`). It is the only check that proves a request came through Tailscale. A trial from a second device showed the identity does arrive through a Tailscale Service (the connection check's Tailscale identity line), so the check is buildable. Also later: bridge-side defaults for the agent command (`dontAsk` with a per-repo allowlist, the sandbox on), which changes what agents can do and is the operator's choice; TOTP.

Skip for now: passkeys (finding 9), tsnet inside the hub (ties the hub to Tailscale and drops LAN-only setups).

## Call

**Proceed** with guards 1 to 7. Guard 3 changes a habit (Agents on from the app) and guard 4 removes a setup option (no password); both are what the stakes call for. Google Calendar and Outlook feeds stop working with a private hub, which the operator accepted.
